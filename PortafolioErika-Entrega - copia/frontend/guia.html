1. Página web, sistema y aplicación

¿Qué es cada uno?

ConceptoDefiniciónEjemplo
Página web Documento HTML que el navegador descarga e interpreta. Muestra contenido y puede incluir estilos (CSS) y comportamiento (JavaScript). frontend/index.html del portafolio.
Sistema Conjunto de componentes que interactúan con un objetivo común, con reglas, datos y permisos. Incluye frontend, backend, base de datos y usuarios. El portafolio completo: sitio público + API + SQLite + login + roles + CRUD.
Aplicación Software interactivo que permite al usuario realizar tareas. Puede ser web, de escritorio o móvil. Aplicación web de gestión del portafolio: el admin crea, edita y elimina contenido.

¿Qué tipo de proyecto desarrollé y qué presento?

Desarrollé una aplicación web (que también funciona como sistema de gestión) para administrar un portafolio personal. El proyecto está separado en:

  • Frontend: HTML, CSS y JavaScript (interfaz, validaciones, DOM, fetch).
  • Backend: Node.js + Express, con rutas, controladores y middlewares.
  • Base de datos: SQLite mediante node:sqlite.
  • Seguridad: contraseñas con hash scrypt, sesiones con token y roles admin/visitante.

En la defensa presento: el portfolio público (proyectos publicados, habilidades y formación cargados desde la base de datos), el login, la diferencia de permisos entre administrador y visitante, y el panel de administración con tres CRUD: proyectos, habilidades/tecnologías y formación académica.

2. Modelo cliente-servidor

Es una arquitectura en la que un cliente pide recursos o acciones y un servidor los procesa y responde. Se comunican mediante HTTP.

  • Cliente: el navegador ejecutando HTML, CSS y JavaScript. Envía peticiones con fetch.
  • Servidor: la aplicación Node.js + Express. Valida datos, consulta SQLite y responde en JSON.
  • Base de datos: guarda usuarios, sesiones, proyectos, habilidades y formación.

Ejemplo real: cargar los proyectos publicados

El frontend pide la lista de proyectos publicados:

// frontend/js/script.js
const proyectos = await api("/api/proyectos?estado=publicado");
renderizarProyectos(proyectos, contenedor);

La función api() arma la petición HTTP y agrega el token de sesión si existe:

// frontend/js/script.js
const respuesta = await fetch(API_BASE + ruta, {
  ...opciones,
  headers,
  credentials: "include",
});

El servidor recibe la petición, revisa la sesión y el rol, consulta la base y responde:

// backend/src/controllers/proyectos.controller.js
if (!esAdmin(req)) {
  const filas = db
    .prepare("SELECT * FROM proyectos WHERE estado = 'publicado' ORDER BY id DESC")
    .all();

  return res.json(filas.map(filaAProyecto));
}
Intercambio completo:
GET /api/proyectos?estado=publicado → respuesta 200 OK con Content-Type: application/json y un arreglo [{ "id": 1, "nombre": "Clínica Dental", ... }]. El cliente recibe ese JSON y crea las tarjetas con document.createElement().

Otro ejemplo: iniciar sesión

El cliente envía POST /api/auth/login con email/usuario y contraseña. El servidor busca al usuario, verifica el hash, crea una sesión y devuelve 200 con el token. Si las credenciales son incorrectas devuelve 401 Unauthorized.

3. HTML

HTML (HyperText Markup Language) es el lenguaje de marcado que define la estructura y el contenido de una página web. El navegador lo lee y construye el DOM. No es un lenguaje de programación: describe qué es cada elemento (título, párrafo, imagen, formulario).

HTML semántico: usar header, nav, main, section y footer (en lugar de solo div) mejora la accesibilidad, el SEO y hace el código más legible.

4. CSS

CSS (Cascading Style Sheets) es el lenguaje que da presentación visual al HTML: colores, tipografías, tamaños, espacios, disposición y adaptación a distintas pantallas. Funciona con reglas: selector + propiedades + valores.

Selectores

TipoEjemplo en el proyectoQué selecciona
Etiquetabody { ... }Todos los elementos <body>.
Clase.proyecto { ... }Todos los elementos con class="proyecto".
ID#contacto { ... }El elemento con id="contacto" (único).
Descendiente.nav a { ... }Los <a> dentro de .nav.
Pseudo-clase.boton:hover { ... }El botón cuando el mouse está encima.
Pseudo-elemento.seccion h2::before { ... }Inserta la barrita decorativa antes del título.
Combinación.estado-publicado, .nivel-avanzadoClases generadas según el dato (estado/nivel).

Especificidad: si dos reglas afectan al mismo elemento, gana la más específica (ID > clase > etiqueta). Si empatan, gana la que aparece más abajo. Además existe la herencia (por ejemplo, font-family del body se hereda).

Modelo de caja

Todo elemento es una caja formada por contenido → padding (relleno) → border (borde) → margin (margen). En el proyecto se usa box-sizing: border-box, lo que hace que width incluya padding y borde; así los tamaños son predecibles. 

/* frontend/css/style.css */
* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

.panel {
  background: var(--color-blanco);
  border-radius: var(--radio);
  padding: 22px;
  box-shadow: 0 4px 14px rgba(124, 58, 237, 0.1);
}

Posicionamiento

  • static: posición normal del flujo (valor por defecto).
  • relative: se desplaza respecto de su posición normal. Ejemplo: .hero-foto.
  • absolute: se ubica respecto del ancestro posicionado más cercano. Ejemplo: la insignia “Disponible” dentro de la foto.
  • fixed: queda fija respecto de la ventana. Ejemplo: el botón “↑”.
  • sticky: se comporta normal hasta que se pega al hacer scroll. Ejemplo: la cabecera.
/* La cabecera queda pegada arriba */
.cabecera {
  position: sticky;
  top: 0;
  z-index: 10;
}

/* El contenedor es la referencia para el badge */
.hero-foto { position: relative; }

/* El badge se posiciona dentro de la foto */
.hero-badge {
  position: absolute;
  bottom: 8px;
  right: 4px;
}

/* El botón de volver arriba queda fijo en la ventana */
.btn-subir {
  position: fixed;
  bottom: 22px;
  right: 22px;
}

Flexbox, Grid y responsive

Flexbox se usa para filas y alineación (por ejemplo .barra, .hero-contenido, .form-gestion). Grid se usa para grillas de columnas (por ejemplo .proyectos, .sobre-grid, .formacion). Las media queries adaptan el sitio a pantallas chicas. 

.proyectos {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 20px;
}

@media (max-width: 900px) {
  .proyectos { grid-template-columns: 1fr; }
  .sobre-grid { grid-template-columns: 1fr; }
}

5. JavaScript y DOM

JavaScript es un lenguaje de programación que se ejecuta en el navegador (y también en el servidor con Node.js). En una aplicación web permite interactividad: responder a eventos, validar formularios, modificar la página y comunicarse con el servidor.

¿Qué es el DOM?

El DOM (Document Object Model) es la representación en forma de árbol que el navegador construye a partir del HTML. Cada etiqueta es un nodo/elemento al que JavaScript puede leer y modificar (texto, atributos, estilos, clases). Cuando el DOM cambia, la página se actualiza. 

<body>
  <header>...</header>
  <main>
    <section id="proyectos">
      <div id="listaProyectos">...</div>
    </section>
  </main>
</body>

Uso en el proyecto

  • Seleccionar elementos: document.getElementById("listaProyectos").
  • Escuchar eventos: addEventListener("click", ...), "submit", "input".
  • Crear elementos: document.createElement("article") y appendChild().
  • Cambiar contenido: textContent (seguro, no interpreta HTML).
  • Cambiar clases/estado: classList.toggle("oculto", ...).
  • Evitar el envío tradicional: evento.preventDefault() y usar fetch.
// frontend/js/script.js — construir una tarjeta de proyecto en el DOM
proyectos.forEach((proyecto, indice) => {
  const articulo = crearElemento("article", "proyecto");

  articulo.appendChild(
    crearElemento("span", "proyecto-num", String(indice + 1).padStart(2, "0"))
  );

  articulo.appendChild(crearElemento("h3", null, proyecto.nombre));
  articulo.appendChild(crearElemento("p", null, proyecto.descripcion));

  contenedor.appendChild(articulo);
});

En el login se ve el ciclo completo: el usuario envía el formulario, se llama a evento.preventDefault(), se hace fetch al servidor, se guarda el token y se actualiza la interfaz (chip de usuario, panel visible, etc.).

En este proyecto TypeScript se usa en el backend para los modelos y las validaciones:

// backend/src/models/proyecto.ts
export interface Proyecto {
  id: number;
  nombre: string;
  descripcion: string;
  tecnologias: string[];
  imagenUrl: string | null;
  enlaceUrl: string | null;
  estado: EstadoProyecto;
}

export function validarProyecto(datos: Partial<ProyectoEntrada>): string[] {
  const errores: string[] = [];
  if (!datos.nombre || datos.nombre.trim().length < 3) {
    errores.push("El nombre debe tener al menos 3 caracteres.");
  }
  return errores;
}

tsc compila src/models/*.ts a dist/models/*.js y los controladores de Express consumen el resultado. El frontend se mantiene en JavaScript puro; TypeScript no se ejecuta en el navegador directamente, sino que se transforma a JavaScript.

7. Peticiones y respuestas HTTP

HTTP es el protocolo de comunicación cliente-servidor. Una petición tiene un método, una URL, encabezados y, a veces, un cuerpo. La respuesta tiene un código de estado, encabezados y un cuerpo (por ejemplo, JSON).

Métodos utilizados en el proyecto

MétodoPara qué sirveEjemplo en el proyecto
GET Consultar/leer un recurso sin modificarlo. GET /api/proyectos?estado=publicado, GET /api/habilidades, GET /api/formacion, GET /api/auth/sesion.
POST Crear un recurso nuevo o iniciar una acción (login). POST /api/auth/login, POST /api/proyectos, POST /api/habilidades, POST /api/formacion.
PUT Modificar/actualizar un recurso existente. PUT /api/proyectos/3, PUT /api/habilidades/2, PUT /api/formacion/1.
DELETE Eliminar un recurso. DELETE /api/proyectos/3, DELETE /api/habilidades/8, DELETE /api/formacion/2.

Ejemplos de peticiones reales del frontend

// GET: listar habilidades
const habilidades = await api("/api/habilidades");

// POST: crear un proyecto (solo admin)
await api("/api/proyectos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    nombre: "Nuevo proyecto",
    descripcion: "Descripción del proyecto",
    tecnologias: "HTML, CSS",
    estado: "borrador",
  }),
});

// PUT: actualizar un proyecto existente
await api("/api/proyectos/" + id, { method: "PUT", body: JSON.stringify(datos) });

// DELETE: eliminar
await api("/api/proyectos/" + id, { method: "DELETE" });

8. Manejo de usuarios y sesiones

El manejo de usuarios consiste en registrar identidades, validar credenciales y asignar permisos. Una sesión es el estado que indica que un usuario ya se autenticó; se mantiene entre peticiones para no pedir la contraseña cada vez.

Usuarios y roles

  • Administrador: accede al panel y puede crear, consultar, modificar y eliminar proyectos, habilidades y formación.
  • Visitante: accede al portfolio público y consulta proyectos publicados, habilidades y formación. No puede escribir.
  • No hay registro público: los usuarios se cargan en la base al iniciar (usuario administrador pre-registrado).

Contraseñas seguras (hash)

Las contraseñas no se guardan en texto plano. Se guarda un hash scrypt con una sal aleatoria distinta por usuario: scrypt$<salt>$<hash>. Al iniciar sesión se vuelve a calcular el hash con la misma sal y se comparan de forma segura. 

// backend/src/seguridad.js
function hashPassword(password) {
  const salt = crypto.randomBytes(16).toString("hex");
  const hash = crypto.scryptSync(password, salt, 64);
  return `scrypt$${salt}$${hash.toString("hex")}`;
}

function verificarPassword(password, passwordGuardado) {
  const [, salt, hashHex] = passwordGuardado.split("$");
  const esperado = Buffer.from(hashHex, "hex");
  const calculado = crypto.scryptSync(password, salt, 64);
  return crypto.timingSafeEqual(esperado, calculado);
}

¿Cómo funciona la sesión en este proyecto?

  1. El usuario envía email/usuario y contraseña por POST /api/auth/login.
  2. El backend busca al usuario en SQLite y verifica el hash.
  3. Si coincide, genera un token aleatorio de 32 bytes y lo guarda en la tabla sesiones con fecha de expiración (8 horas).
  4. Devuelve el token y además lo envía en una cookie httpOnly (JavaScript no puede leerla, lo que reduce el riesgo de XSS).
  5. En cada petición posterior, el cliente envía el token: por cookie o con Authorization: Bearer <token>.
  6. El middleware sesionOpcional valida el token y carga req.sesion.
  7. requiereAdmin verifica el rol antes de ejecutar escrituras; si no corresponde responde 401 o 403.
  8. Al cerrar sesión (POST /api/auth/logout) se elimina el registro de la base y se borra la cookie.
// backend/src/middlewares/auth.js
function requiereAdmin(req, res, next) {
  if (!req.sesion) {
    return res.status(401).json({ error: "Debés iniciar sesión." });
  }

  if (req.sesion.usuario.rol !== "admin") {
    return res.status(403).json({ error: "No tenés permisos de administrador." });
  }

  next();
}
Prueba clave para la defensa: iniciar sesión como visitante y, desde la consola del navegador, intentar POST /api/proyectos con su token. El servidor responde 403 Forbidden: la seguridad no depende de ocultar botones, se valida en el backend.

Diferencia entre autenticación y autorización: autenticación responde “¿quién sos?” (login); autorización responde “¿qué podés hacer?” (rol y permisos).

9. Recorrido de demostración en vivo

Orden sugerido para mostrar el proyecto durante la defensa:

  1. Abrir el sitio público en http://localhost:3000: mostrar proyectos publicados, habilidades y formación traídos de la base.
  2. Abrir DevTools → Network y recargar: señalar los GET a /api/proyectos?estado=publicado, /api/habilidades y /api/formacion, con sus respuestas JSON.
  3. Ingresar como administrador (admin@erika.com / Admin123!): mostrar el POST /api/auth/login (200), el token y el panel que aparece.
  4. Crear un proyecto: mostrar POST /api/proyectos (201), la validación del backend y el nuevo registro en la tabla.
  5. Editar el proyecto: mostrar PUT /api/proyectos/:id (200). Eliminarlo: mostrar DELETE (204).
  6. Repetir el CRUD con una habilidad y con un registro de formación.
  7. Cerrar sesión: mostrar POST /api/auth/logout (204) y cómo desaparece el panel.
  8. Ingresar como visitante (visitante@erika.com / Visita123!): no aparece el panel. En consola, intentar un POST o DELETE y mostrar el 403.
  9. Mostrar el código: HTML semántico, CSS (modelo de caja y posicionamiento), JavaScript/DOM, modelos TypeScript, rutas, controladores, middleware y esquema SQLite.
